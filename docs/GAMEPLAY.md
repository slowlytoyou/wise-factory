# WISE FACTORY 플레이 가이드

[프로젝트 소개와 빠른 시작](../README.md)

**채굴 → 운반 → 가공 → 상인에게 판매.** 터미널 안에서 돌아가는 탑뷰 자동화 공장입니다. WASD로 41×29 맵을 돌아다니며 설비를 배치하고, 중앙 상인에게 컨베이어를 연결하세요. 공장은 조작하지 않아도 계속 생산합니다.

## 실행

Node.js 20 이상이면 추가 패키지 설치 없이 실행할 수 있습니다. **기본은 개인 로컬 플레이입니다. 회원가입·로그인·인터넷 연결 없이 모든 게임 기능을 사용할 수 있습니다.**

```sh
npm start
# 동일한 개인 모드를 명시적으로 선택하려면:
npm run local
```

채굴·설계도·레이더·전송기·환생은 모두 개인 플레이에서 제공되고 이 기기에 자동 저장됩니다. 로그인 정보나 클라우드 설정이 있더라도 `npm start`는 항상 개인 공장을 엽니다. 클라우드 저장과 다른 플레이어와의 순위 비교는 `npm run cloud`로 따로 선택하는 기능입니다.

**`npm run demo`**는 기어·회로·강철 생산 라인이 미리 연결된 공장을 보여 줍니다. 데모에서도 이동·설치·강화할 수 있으며 저장 파일은 읽거나 쓰지 않습니다.

터미널은 **120열 × 40행**을 권장합니다. 88열 × 30행부터 플레이할 수 있고, 작은 화면에서는 카메라가 플레이어를 따라갑니다. UTF-8과 한글이 표시되는 고정폭 글꼴을 사용하세요. 애니메이션은 기본 24 FPS입니다.

## 첫 번째 공장

1. 시작하면 철광석 채굴기와 중앙 상인까지 이어진 기본 벨트가 있습니다. 자금 300코인으로 확장하세요.
2. `WASD`로 `@`를 움직입니다. `@`가 있는 칸에 설비를 설치합니다. 캐릭터는 설비 위로도 지나갈 수 있습니다.
3. `1` 채굴기를 선택하고 **광맥 위**에서 `E`를 누릅니다. 처음에는 서쪽 철과 남서쪽 돌이 보입니다. 구리·석탄·원목·석영·금은 상점의 레이더로 순서대로 발견합니다.
4. `2` 벨트를 선택하고 이어 붙입니다. `R`로 배출 방향을 바꾸세요. 벨트 끝이 상인의 중앙 3×3 구역에 닿으면 자동 판매됩니다.
5. 중앙 상인 구역 또는 인접 칸에서 `B`를 눌러 **설계도를 먼저 구매**합니다. 해금 후 `3` 용광로 또는 `4` 조립기를 놓고 `F`로 제작법을 선택하세요. 설비 건설비는 설계도 가격과 별도이며, 여러 방향의 벨트가 같은 모듈로 들어갈 수 있습니다.
6. 설비 위에서 `U`로 Lv.5까지 강화합니다. 채굴·가공 속도와 벨트 운반 속도가 올라갑니다. 상점에서 전송기를 사면 중앙까지 벨트를 길게 연결하지 않고 원하는 위치에서 판매할 수 있습니다.

아이템은 실제로 벨트를 이동합니다. 출구가 막히면 기다리고, 생산 모듈의 재료가 부족하면 가공을 멈춥니다. 생산 모듈은 선택된 제작법에 필요한 재료만 받습니다. 별도의 인서터 없이 인접한 설비로 직접 넘길 수 있습니다.

벨트는 **한 칸당 물건 하나**를 보관합니다. 출구가 막히면 뒤쪽 벨트까지 차례로 가득 차며, 기다리는 광물은 그 자리에 고정됩니다. 물건 그림은 실제 다음 칸으로 전달될 때만 이동합니다. 벨트는 뒤와 옆에서 물건을 받을 수 있고, 배출구 쪽에서는 받지 않습니다. 서로 마주 보는 `→←` 벨트는 왕복 운반하지 않고 막힙니다. `R`로 방향을 바로잡거나 출구를 연결하면 다시 운반합니다.

## 조작

| 키 | 동작 |
| --- | --- |
| `W A S D` / 방향키 | 이동, 작은 화면에서는 카메라 추적 |
| `1` / `2` / `3` / `4` / `5` | 채굴기 / 컨베이어 / 용광로 / 조립기 / 판매 전송기 선택 |
| `E` / `Space` | 현재 칸에 설치 |
| `R` | 설치 방향 변경, 설비 위에서는 그 설비 회전 |
| `U` | 현재 칸의 설비 강화 |
| `X` / `Backspace` | 철거, 투자 비용의 절반 환급; 내부 재료 폐기. 전송기는 재고로 회수 |
| `F` | 선택한 생산 모듈 또는 현재 칸 설비의 제작법 변경 |
| `B` | 중앙 상인 근처에서 상점 열기. `W/S`·숫자로 선택, `A/D`로 페이지, `E/Enter`로 구매 |
| `T` | 환생 보상과 초기화 범위 확인. `E/Enter` 다음 `Y`로 확정 |
| `C` | 전체 제작법과 판매가 도감. `W/S` 선택, `A/D` 페이지, `Enter` 제작법 지정 |
| `L` | 개인 플레이: 내 공장 기록 / 클라우드 플레이: 월간 순위·최근 60초 골드/초·총 플레이 시간 |
| `K` | 스킨 선택. `W/S`·`1/2/3` 선택, `Enter` 적용, `Esc` 취소 |
| `N` | 닉네임 설정. `Enter` 저장, `Esc` 취소, `Ctrl+U` 전체 삭제 |
| `G` | 클라우드 모드에서만 재연결; 개인 모드에서는 저장 방식 안내 |
| `P` | 로컬 게임 정지·재개; 온라인은 화면만 정지 |
| `?` / `H` | 도움말 |
| `Esc` | 상점·도움말·도감·리더보드 닫기, 환생 취소 |
| `Q` / `Ctrl+C` | 저장하고 종료 |

제작법을 바꾸면 재료와 완성품은 보존되고 가공 진행률은 초기화됩니다. 설비를 회전시켜 잘못 연결된 물류를 수정할 수 있습니다.

## 상인 상점과 탐사

| 품목 | 가격 | 효과 |
| --- | --- | --- |
| 용광로 설계도 | 200 | 용광로 건설 해금; 건설비 90 |
| 조립기 설계도 | 700 | 용광로 설계도 구매 후 구입 가능; 조립기 건설비 140 |
| 구리 탐지 레이더 | 350 | 북동쪽 구리 광맥 표시 및 채굴 허용 |
| 석탄 탐지 레이더 | 900 | 구리 레이더 구매 후 북쪽·남동쪽 석탄 광맥 표시 |
| 판매 전송기 | 개당 250 | 설치 가능한 판매 지점 1개. 반복 구매 가능 |
| 원목 탐지 레이더 | 1,800 | 석탄 레이더 필요. 북서쪽 숲에서 원목 채취 |
| 석영 탐지 레이더 | 3,600 | 원목 레이더 필요. 북동쪽 석영 광맥 해금 |
| 금 탐지 레이더 | 7,200 | 석영 레이더 필요. 남동쪽 금광 해금 |

설계도와 레이더는 회차마다 한 번 구매합니다. 탐지하지 않은 광맥은 평지로 보이고 그 위에 채굴기를 설치할 수 없습니다. 레이더는 구매 즉시 적용됩니다.

전송기는 `5`로 선택해 빈 칸에 `E`로 설치합니다. 추가 건설비 없이 재고 1개를 소모하고, 인접한 벨트나 생산 모듈에서 들어온 물건을 모든 방향에서 받아 즉시 판매합니다. 전송기에는 강화나 배출 방향이 없으며, `X`로 회수하면 코인 대신 전송기 1개가 재고로 돌아옵니다.

## 환생

이번 회차 판매액이 **5,000코인** 이상이면 `T`에서 환생할 수 있습니다. 획득하는 OH 코어는 `floor(sqrt(회차 판매액 / 5000))`개입니다. 5,000에서 1개, 20,000에서 2개, 45,000에서 3개를 받습니다. 보유 코어 1개마다 모든 판매가에 기본 가격의 **25%가 영구적으로 추가**됩니다. 코어 2개면 기본 판매가의 1.5배입니다. 코어는 **보유만 하면 자동 적용되며 소모되지 않습니다.** 상인·전송기 판매에 모두 적용되고, 4개면 판매가가 2배입니다. 환생 조건을 채우기 전에도 `T` 화면에서 이 설명을 확인할 수 있습니다.

- 초기화: 현재 설비·재료·자금·회차 통계·설계도·레이더·전송기. 기본 철 채굴 라인과 300코인으로 다시 시작합니다.
- 유지: OH 코어·환생 횟수·전체 누적 판매액·전체 판매 수량. 환생해도 현재 월의 리더보드 점수와 클라우드 총 플레이 시간은 유지됩니다.
- 환생 화면에서 받을 코어와 배율을 확인한 뒤 `E/Enter` → `Y`를 눌러야 실행됩니다. `Esc`로 취소할 수 있습니다.

이 업데이트 이전의 v2 저장은 기존 설비·광맥을 보존하도록 용광로·조립기와 두 광맥이 해금된 상태로 이어집니다. 다음 환생부터 새로운 해금 순서를 따릅니다. 새 게임으로 시작하려면 `node src/main.mjs --save ./new-factory.save.json`을 사용하세요.

**최상위 생산물은 논문**입니다. 원목→펄프→종이, 석영→유리·실리콘, 금→금괴를 기존 금속 생산 라인과 결합해 반도체·센서·연구장비·실험데이터를 만들고, 실험데이터 2 + 종이 3 + 반도체 1로 논문을 집필합니다. 논문 기본 판매가는 **6,000코인**이며 OH 코어의 판매 보너스도 적용됩니다. 총 원재료 7종, 가공품 18종입니다.

도감과 상점은 작은 화면에서도 모든 품목을 페이지로 볼 수 있습니다. `W/S` 또는 위아래로 선택하고 `A/D`·좌우·Page Up/Down으로 페이지를 이동합니다. Home/End는 처음/마지막 품목으로 이동합니다. 도감에서 `Enter`를 누르면 해당 설비와 제작법이 선택되며, 같은 종류의 설비 위라면 제작법을 바로 바꿉니다.

원물 판매가는 철광석 2, 구리광석 3, 석탄 2, 돌 1, 원목 5, 석영 6, 금광석 10코인입니다. 채굴기는 Lv.1 기준 4초마다 원물 하나를 만듭니다. 레벨에 비례해 채굴·가공 속도가 증가하며, 벨트는 레벨에 따라 초당 1~5회의 운반 단계를 처리합니다. 물류 병목은 별도로 해결해야 합니다.

## 개인 저장과 선택적 클라우드

로컬 공장은 10초마다, 그리고 종료 시 `~/.local/state/starfall/factory-v2.json`에 저장합니다. 기존 공장을 자동으로 이어가기 위해 파일 경로는 유지하며, 내부 저장 형식은 **v3**으로 갱신합니다. 구버전 게임은 v3를 읽거나 덮어쓰지 못합니다. `XDG_STATE_HOME`을 지정했다면 해당 경로를 사용합니다. 게임은 실행 중에만 생산합니다. 종료하거나 컴퓨터가 잠든 동안에는 생산하지 않으며, 다시 접속하면 저장한 상태에서 이어 갑니다. 로컬 모드에서 `P`를 누르면 생산도 멈춥니다.

**개인 플레이는 클라우드 설정과 독립적으로 실행됩니다.** 시작·자동 저장·종료·`L` 내 기록 조회 중에는 클라우드 설정이나 로그인 세션을 읽지 않고 서버 요청도 하지 않습니다. 클라우드 연결 실패는 개인 공장에 영향을 주지 않습니다.

저장소에는 공유 서버의 URL과 공개 연결 키가 포함되어 있습니다. Supabase 계정이나 별도 서버 설정 없이 본인의 GitHub 계정으로 로그인하면 됩니다. 클라우드 게임에서 `L`을 누르면 같은 서버를 사용하는 플레이어의 월간 순위와 최근 60초 골드/초, 총 플레이 시간을 볼 수 있습니다.

```sh
git pull                  # 이미 내려받은 저장소를 최신 버전으로 업데이트
npm run login -- github    # 본인 GitHub 계정으로 로그인; 최초 로그인 시 계정 생성
npm run cloud
node src/main.mjs --cloud --nickname "철의 공장"
node src/main.mjs --leaderboard
node src/main.mjs --logout
```

로그인 세션과 클라우드 공장은 계정마다 분리됩니다. 다른 기기에서 이어서 플레이하려면 같은 GitHub 계정으로 로그인하세요. 로그인만으로 개인 공장이 클라우드로 전환되지는 않습니다. 클라우드 명령이 실패하면 `npm start` 또는 `npm run local`로 개인 저장을 계속할 수 있습니다. 두 모드는 저장 슬롯이 달라 자동 전환하거나 합치지 않습니다.

게임에서 **`N`을 눌러 닉네임을 변경**할 수 있습니다. 2~20자의 문자·숫자·공백·`_`·`-`를 사용하며 `Enter`로 저장합니다. 개인 닉네임은 해당 저장 파일에 보관되고 환생 후에도 유지됩니다. 클라우드 닉네임은 서버 확인 후 화면과 리더보드에 반영됩니다. 입력 중에는 이동·건설·종료 단축키가 이름의 글자로 입력되며 `Esc`로 취소할 수 있습니다. 실행할 때 `--nickname "은하 공장"`으로 지정하는 방법도 지원합니다.

- **로컬 공장과 클라우드 공장은 별도 슬롯**입니다. 첫 클라우드 접속에는 기본 공장을 생성하고, 이후 같은 계정으로 접속하면 서버에 저장한 공장을 이어 갑니다. 수정 가능한 로컬 세이브는 클라우드 순위에 가져오지 않습니다.
- 클라우드는 서버가 실행 중인 클라이언트의 생산 시간·건설/상점 비용·재료·매출·환생 코어를 검증하고 계산합니다. 클라이언트는 점수·코어·저장 원문을 업로드하지 않습니다.
- 건설 명령은 모아서 최소 0.6초 간격으로 전송하고, 조작이 없을 때도 약 3초마다 동기화합니다. 화면 애니메이션과 WASD 이동은 로컬에서 처리합니다.
- 서버 요청 제한이 걸리면 화면에 대기 상태를 표시하고 서버가 안내한 시간이 지난 뒤 자동으로 다시 시도합니다. 로그인 만료는 별도로 안내합니다.
- 연결이 끊기면 생산·건설·상점 구매·환생을 잠시 멈추고 `[G]`로 재연결할 수 있습니다. 재시도에는 같은 요청 ID를 사용해 중복 구매나 중복 환생 보상을 방지합니다.
- 여러 기기에서 동시에 수정하면 충돌을 감지해 서버 상태로 돌아갑니다. 자금을 합산하지 않습니다.
- `P`는 클라우드 모드에서 화면만 멈춥니다. 프로그램이 실행되고 서버에 연결된 동안에는 생산을 계속합니다. 종료·컴퓨터 절전·연결 중단 동안의 생산은 적립하지 않습니다. 순위는 마지막 서버 동기화 시점에 확인된 이번 달 판매액 기준입니다.
- 클라우드 종료 시 짧은 동기화 대기를 마치고 마지막 건설까지 서버 반영을 확인합니다. 네트워크 오류나 긴 요청 제한으로 확인하지 못했다면 저장 실패를 안내하며, 다음 접속은 마지막 서버 확인 상태에서 시작합니다.
- `--save PATH`는 개인 저장에만 사용할 수 있습니다. `--cloud`와 함께 지정하면 개인 파일을 보호하기 위해 실행을 거부합니다.

**최근 60초 골드/초 = 최근 60초 동안 실제 판매한 골드 ÷ 60**입니다. 서버가 확인한 판매 시각과 금액을 사용하며, 조회 시각을 기준으로 지난 60초를 계산합니다. 골드는 게임의 자금(코인, ₵)과 같고 업그레이드·구매 비용은 판매액에서 빼지 않습니다. 예를 들어 최근 60초에 120골드를 판매하면 2골드/초이며, 접속한 지 60초가 되지 않았어도 분모는 60입니다. 생산물을 쌓아 두기만 하면 판매액에 포함되지 않고, 판매가 끊기면 이전 판매 기록이 60초 구간에서 빠지며 0으로 내려갑니다. 최근 판매 시각은 이 업데이트 이후부터 기록하므로 과거 월간 판매액은 이 수치에 포함하지 않습니다.

**월간 순위는 매월 1일 00:00, 한국 시간(Asia/Seoul)에 새 시즌으로 전환됩니다.** 월간 판매액 점수는 새 달 기준으로 시작하며, 최근 60초 골드/초는 월 경계와 관계없이 계속 계산합니다. 공장·자금·누적 판매액·OH 코어는 유지됩니다. 실행·연결 중 서버가 확인한 생산만 기록하며, 월 경계를 넘는 판매는 각 월에 나누어 집계합니다. 이전 버전에서 이미 받은 자원·OH 코어·판매 기록은 유지합니다.

**총 플레이 시간은 월 전환이나 환생으로 초기화되지 않습니다.** 이 기능 업데이트 이후 게임이 실행되고 서버에 연결된 시간을 계정별로 누적합니다. 종료·컴퓨터 절전·연결 중단 시간은 제외하고, 클라우드 모드에서 `P`로 화면만 멈춘 동안에는 생산과 함께 시간이 계속 쌓입니다. 이전 버전은 실제 접속 시간을 따로 보관하지 않아 업데이트 전 시간은 합산하지 않습니다. 로컬 플레이 시간은 클라우드 순위에 포함하지 않습니다.

열어 둔 리더보드는 약 3초마다, 그리고 서버가 알려 준 월 전환 시점에 자동 갱신됩니다. 클라우드 저장도 약 3초마다 반영하므로 네트워크 상태에 따라 몇 초의 표시 지연은 있을 수 있습니다. 서버에서 확인한 생산과 판매를 기준으로 계산합니다.

이전 버전은 `npm run classic`으로 실행할 수 있으며 기존 `save.json`을 그대로 사용합니다.

## 옵션과 검증

```sh
node src/main.mjs --fps 30
node src/main.mjs --save ./my-factory.save.json
node src/main.mjs --no-color
npm run snapshot
node src/main.mjs --demo --snapshot
npm test
npm run test:pty
npm run test:cloud-pty
```

`NO_COLOR`도 지원합니다. 게임에는 Node.js만 필요하고, 선택적인 PTY 입력 검증에는 macOS/Linux와 Python 3을 사용합니다. OAuth 단위 테스트는 가짜 인증 응답과 로컬 루프백 서버를 사용하며 실제 계정이나 외부 서버에 접속하지 않습니다.

## 구조

| 경로 | 역할 |
| --- | --- |
| `src/main.mjs` | 키 입력·애니메이션·로컬 및 클라우드 모드 |
| `src/factory-render.mjs` | 탑뷰 맵·카메라·물류 애니메이션·UI |
| `supabase/functions/_shared/factory.mjs` | 클라이언트와 서버가 공유하는 공장 시뮬레이션 |
| `src/factory-save.mjs` | v3 원자적 저장, 기존 v2 이관과 저장 상태 복원 |
| `src/cloud.mjs` | 소셜 로그인·세션 갱신·API 통신 |
| `src/cloud-game.mjs` | 명령 동기화·충돌 처리·재시도 |
| `supabase/functions/` | 서버가 검증하는 공장 API와 리더보드 |
| `supabase/migrations/` | 비공개 저장 테이블·접근 제어·중복 요청 방지 |

저장 파일이 손상되면 원본을 덮어쓰지 않습니다. 새 파일 경로를 지정해 별도 공장을 시작할 수 있습니다.

## 스킨과 표시 설정

`K`에서 **Original Skin**, **Work Skin**, **Work Skin · Dev** 중 하나를 선택합니다. Work Skin은 업무용 터미널처럼 차분한 색상과 격자·파이프·노드로 표시하며 장식 애니메이션을 줄입니다. 첫 번째 Work Skin은 게임 용어를 그대로 사용합니다. Dev는 게임의 이름과 안내를 프로그래밍 작업에 대응하는 용어로 표시합니다.

| 게임 용어 | Work Skin · Dev |
| --- | --- |
| 공장 / 중앙 상인 | 프로젝트 / 패키지 저장소 |
| 채굴기 / 컨베이어 | 수집기 / 파이프라인 |
| 용광로 / 조립기 / 전송기 | 빌드 워커 / 통합 워커 / 배포 훅 |
| 철광석 / 철판 | 소스코드 / 모듈 |
| 회로 / 반도체 | 서비스 / 컴파일러 |
| 연구장비 / 실험데이터 / 논문 | 테스트 환경 / 벤치마크 / 기술 백서 |
| 골드 / 판매 | 크레딧 / 배포 |
| 환생 / OH 코어 | 리팩터링 / 설계 포인트 |

스킨은 조작·생산 규칙과 같은 저장 데이터를 표현하는 방식입니다. 기존 공장의 배치, 돈, 제작법, 닉네임, 리더보드 점수를 그대로 사용합니다.

선택은 `~/.local/state/starfall/preferences.json`에 별도로 저장합니다. `XDG_STATE_HOME`을 설정했다면 그 아래 `starfall/preferences.json`을 사용합니다. 설정은 기기 단위이며 클라우드 공장에 전송하지 않습니다. 게임 저장 경로를 `--save`로 바꾸어도 스킨 설정 경로는 유지됩니다. 설정 파일에 문제가 있으면 원본을 보존하고 Original Skin으로 시작합니다.

`--skin original`, `--skin work`, `--skin work-dev`로 해당 실행의 스킨을 지정할 수도 있습니다. `--help`와 `--snapshot`은 설정 파일을 읽거나 쓰지 않으며, 데모에서 스킨을 바꿔도 다음 실행의 설정은 변경하지 않습니다.
